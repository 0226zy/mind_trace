# 止念小程序产品设计与交互设计重设计提案

> 文档状态：核心重构已实施，原生编译通过；IDE 与真机渲染待验证
>
> 设计范围：微信小程序 P0 全流程与视觉语言
>
> 设计依据：现有《产品设计与交互设计》、当前小程序实现，以及用户提供的《打卡小程序》HTML 参考稿
>
> 实施边界：本稿不修改数据模型、云函数、HTTP API、离线一致性规则或双后端策略

---

## 1. 设计结论

这次重设计不做一次表层的“换皮”，而是重新分配用户注意力：

1. **此刻只负责安顿当下**：首页只保留一个强主动作“记录思虑”，统计和应急退到辅助层级。
2. **书写只负责写下正文**：记录第一阶段不展示情绪、强度、进度、字数或其他评估字段。
3. **保存后即可结束**：默认动作是“回到此刻”，情绪和强度可选，“现在评估”只是次要动作。
4. **处理时一次只看一个问题**：七步评估保留完整规则，但每屏只承载当前步骤。
5. **思虑库以内容为主**：正文和标题优先，状态、强度、版本和时间收缩为一行辅助信息。
6. **异常不压过正文**：离线与同步错误清楚、可恢复，但不使用大面积高饱和警告抢占首屏。
7. **借鉴秩序，不移植打卡业务**：不引入签到、连续天数、补签、勋章、排名或催收提醒。

目标不是让界面“看起来空”，而是让用户在任何时刻都清楚：**现在最重要的一件事是什么，完成后可以去哪里，出问题后内容是否还在。**

## 2. 产品定位与边界

### 2.1 产品定位

止念是一个帮助用户登记思虑、拉开与念头的距离，并在合适的时候进行结构化处理的工具。

核心闭环：

**写下来 → 暂时放下 → 准备好时评估 → 看见变化或复发 → 收尾或继续观察**

“写下来”本身就是一次完整使用，不以完成七步评估作为记录成功的前提。

### 2.2 目标用户与场景

- 脑中反复出现一件事，想先把它从脑海里移出来。
- 情绪较强，暂时不适合分析，只需要一个低负担出口。
- 平静后愿意梳理事实、风险、概率和可控行动。
- 同类思虑再次出现，希望看见历史版本和自己的变化。

### 2.3 非目标

- 不是效率打卡或习惯养成产品。
- 不追求每日打开次数、连续使用天数或评估完成率。
- 不用统计数据评价用户“表现好不好”。
- 不提供医疗诊断、心理治疗或紧急救援承诺。
- 不自动判断相似思虑就是同一件事，不替用户做关联决定。

### 2.4 必须保留的业务约束

| 领域 | 保留规则 |
| --- | --- |
| 正文 | 1–1000 字；第一阶段只写正文；短标题由首个非空行生成 |
| 草稿 | 未提交正文自动保存在本机，异常时不得擅自删除 |
| 感受 | 保存正文后再补充；情绪多选，强度为 2／4／6／8／10；均可留空 |
| 强度统计 | 未补充时显示“未补充”，不按 0 计入均值 |
| 相似思虑 | 仅提示候选，由用户确认是否关联；不得自动合并 |
| 复发版本 | 每次复发是独立版本；可继承评估内容，但从第一步重新评估；旧版本只读保留 |
| 七步评估 | 判断、风险、概率、可控行动、不可控、三种视角、三项确认；可暂存、退出、搁置、恢复 |
| 收尾 | 仅通过专门接口和服务端校验完成；已收尾内容只读；不能离线直接收尾 |
| 应急 | 无需登录、网络或已有记录；不生成思虑记录，不覆盖其他草稿 |
| 离线 | 仅合法 `queued` 项自动同步；异常项人工核对，沿用原 `clientRequestId` |
| 双后端 | 默认微信云开发，保留 HTTP；两套数据独立，不同步、不迁移、不合并 |
| 登录 | cloud 模式不调用 `wx.login`；HTTP 模式才以 `wx.login` 换取 token |
| 注销 | 输入“删除全部数据”；服务端确认成功后才清空本机数据；失败保留会话与本机内容 |

## 3. 当前问题诊断

### 3.1 首页缺少唯一视觉中心

记录、今日统计、待处理数量、处理入口和应急说明同时出现，形成多个竞争点。“记录思虑”应是唯一强主动作，而不是众多卡片中的一个。

### 3.2 保存后的动作鼓励过度处理

“现在评估”若作为最强按钮，会让每次书写都自然通向长流程，削弱“登记后可以回到当下”的产品价值。

### 3.3 元信息包围正文

版本、状态、强度、时间、复发次数、步骤和进度同时展示时，用户看到的是一条“数据记录”，而不是自己曾经写下的内容。

### 3.4 异常区域压过主任务

本机队列、账号变化、后端变化和同步失败若同时展开，会占据处理页的主要空间。错误必须可见，但应先成为摘要，再按需提供详情与恢复动作。

### 3.5 筛选和控件密度过高

大量筛选项、标签和同级按钮会让界面更像管理后台。止念需要的是连续、安静的阅读与处理，而不是展示所有可操作能力。

### 3.6 反馈需要更连续

加载、空内容、失败、离线和完成状态应属于同一个页面结构。不能成功时内容消失、失败时只弹一个 toast，或让用户在弹窗后找不到下一步。

## 4. 设计原则

### 4.1 一屏一重心

每屏只设置一个视觉最强的动作。其他动作仍存在，但通过文字按钮、分组和留白降低层级。

### 4.2 先内容，后属性

先展示“我写了什么”，再展示“它是什么状态”。状态、强度和时间不插到正文之前。

### 4.3 先允许结束，再提供继续

保存正文、完成单项应急工具和退出评估都应是完整结果，不用连续引导把用户留在产品里。

### 4.4 用分组代替卡片堆叠

相关内容使用留白与细线分组。只有需要明确边界或承载一个完整任务的对象才使用卡片。

### 4.5 安静不等于隐藏风险

降低错误的视觉音量，不等于淡化后果。所有异常都必须说明：

- 内容是否仍保留；
- 当前是否已同步；
- 用户现在能做什么；
- 是否会自动重试。

### 4.6 不使用压力式增长机制

不使用红点催收、连续记录、中断警告、成就庆祝、目标完成率或疗效评分。完成反馈采用中性事实表达，如“已经记下”“已收尾”。

## 5. 信息架构

底部保留三个 Tab，不增加第四个“我的”Tab。

```text
止念
├─ 此刻
│  ├─ 记录思虑
│  │  ├─ 相似思虑确认（有候选时）
│  │  ├─ 补充感受（保存后，可选）
│  │  └─ 回到此刻 / 现在评估
│  ├─ 轻量摘要：今日登记、待处理
│  ├─ 应急叫停
│  └─ 我的（右上角入口）
│     ├─ 账号与数据位置
│     ├─ 本机登记
│     ├─ 统计洞察
│     ├─ 隐私说明
│     └─ 注销与删除
├─ 处理
│  ├─ 待处理 / 已收尾
│  ├─ 本机待同步摘要
│  ├─ 七步评估
│  └─ 收尾结果
└─ 思虑库
   ├─ 搜索与筛选
   ├─ 思虑列表
   └─ 思虑详情
      ├─ 最新版本
      ├─ 历史版本时间线
      └─ 相似复发关联
```

### 5.1 导航规则

- Tab 切换保留各页滚动位置和已加载内容，后台刷新不清空旧内容。
- 记录、评估、应急使用全屏任务页，避免底部 Tab 分散注意力。
- 全屏任务页始终有明确关闭或返回入口。
- 有未提交修改时，关闭不直接丢弃内容；按现有草稿或暂存规则保存并给出轻量状态。
- “我的”从此刻右上角进入，不与核心任务争夺底部导航。

## 6. 核心产品流程

### 6.1 记录主流程

```text
此刻
  ↓ 点击“记录思虑”
只写正文
  ↓ 点击“写好了”
检查正文 → 相似思虑匹配
  ├─ 无候选：直接创建或进入本机队列
  └─ 有候选：用户选择关联版本，或确认作为新思虑
  ↓
已经记下
  ↓ 可选：补充情绪与强度
默认“回到此刻”
  └─ 次动作：“现在评估”（仅已取得服务端记录时）
```

关键决定：

- 书写阶段不出现情绪、强度、触发事件、字数、评估进度和统计。
- 匹配候选不展示相似度百分比，不让精确分数替代用户判断。
- 候选只展示正文摘要、最近登记时间和必要的复发背景。
- “作为新思虑保存”与“关联为现有思虑的新版本”都是明确选择，不预设默认关联。
- 两项感受均可跳过；跳过后不反复提醒补全。
- 在线保存成功后提供“现在评估”；离线入队时不展示该动作。
- 离线反馈使用“已保存在本机，联网后可同步”，不能写成“已保存到云端”。

### 6.2 相似思虑确认流程

1. 标题使用“这可能是同一件事”。
2. 说明使用“只是内容相似，由你决定是否关联”。
3. 每条候选展示内容摘要与一条时间信息，操作文字为“关联这次记录”。
4. 底部提供“都不是，保存为新思虑”。
5. 用户选择前不自动提交；返回时保留正文。
6. 匹配失败时说明“相似内容检查未完成，你仍可保存为新思虑”，不阻断登记。

### 6.3 七步评估流程

```text
处理队列
  ↓
当前步骤
  ├─ 编辑：本机即时暂存，后台同步
  ├─ 上一步 / 下一步
  ├─ 暂存离开
  └─ 暂时搁置
  ↓
第七步：逐项完成三项确认
  ↓
服务端校验并收尾
  ↓
只读结果
```

- 一次只显示一个步骤，保留现有字段和校验。
- 顶部只承担返回、步骤定位和更多操作，不重复页面标题。
- “下一步”是唯一主按钮；最后一步改为“完成收尾”。
- “上一步”为次按钮，“暂存离开”为文字动作，“暂时搁置”收入更多菜单。
- 保存状态使用“已暂存”“正在同步”“同步失败，内容仍在本机”等事实描述。
- 已收尾版本不可编辑；复发产生新版本，不覆盖旧版本。
- 概率输入避免超大数字和夸张滑块，不让自我观察变成打分任务。

### 6.4 应急流程

```text
此刻 / 记录完成页 / 其他允许入口
  ↓
应急叫停（无需登录与网络）
  ├─ 5-4-3 感官落地
  ├─ 一句打断
  └─ 5 分钟抽离
  ↓
完成或随时退出
  ↓
返回进入前页面
```

- 一次只给一个引导，不把多个输入框同时展示成表单。
- 不生成“已叫停”记录，不写思虑，不显示连续次数。
- 不覆盖速记或评估草稿。
- 计时只承诺当前可见页面内行为，不承诺后台精确唤醒。
- 页面持续提供“退出”，退出不需要二次挽留。

### 6.5 离线与恢复流程

```text
本机待同步摘要
  ↓
查看原文与当前状态
  ├─ queued：符合归属规则时自动同步
  ├─ failed：人工确认后沿用原幂等键重试
  ├─ uncertain：先去思虑库核对，再决定是否重试
  └─ blocked：说明账号、后端或环境变化，保留原文
```

- `sending` 中断后进入 `uncertain`，不盲目自动重发。
- 只自动同步归属一致且明确为 `queued` 的项目。
- 技术标识默认收起，不让长幂等字符串占据普通用户视野。
- 任何异常都不能擅自删除本机原文。

### 6.6 注销与删除流程

1. 查看将删除的云端范围和本机范围。
2. 查看本机未同步内容，明确这些内容可能尚未进入云端。
3. 输入“删除全部数据”后启用最终按钮。
4. 请求服务端删除，期间防止重复提交。
5. 仅服务端确认成功后清空本机身份、草稿、队列及其他敏感数据，并回到此刻。
6. 失败时停留在确认层，保留会话、本机内容和持续可见的错误，不自动重试删除。

## 7. P0 页面与交互设计

### 7.1 此刻：唯一重心是记录

**页面目标**：让用户在 3 秒内知道从哪里开始，并允许不做任何分析。

**布局顺序**：

```text
┌─────────────────────────┐
│ 止念                  我的 │
│                         │
│ 把念头先放在这里。        │
│ 不需要现在想明白。        │
│                         │
│ ┌─────────────────────┐ │
│ │      记录思虑        │ │
│ └─────────────────────┘ │
│                         │
│ 今日登记 2 · 待处理 1    │
│                         │
│ ─────────────────────── │
│ 此刻很难受？先叫停      › │
└─────────────────────────┘
```

- 顶部品牌保持克制，“我的”为低层级图标或文字按钮，并提供无障碍标签。
- 主标题只表达当下动作，不使用每日轮换鸡汤或夸张插画。
- “记录思虑”是页面唯一实心主按钮，最小高度 96rpx。
- 摘要使用轻量文字；点击“待处理”可进入处理页，但不另加一张统计卡。
- 应急入口保持可见，以细分隔线和一行文字承载，不使用红色警告或大面积说明。
- 首次使用且无数据时隐藏统计数字，保留一句“写下来，就可以先放下”。

### 7.2 全屏速记：第一阶段只有正文

**页面目标**：让用户把注意力放在念头本身。

```text
┌─────────────────────────┐
│ 关闭       记录思虑       │
│                         │
│ 此刻在想什么？            │
│ 写下来就好。              │
│                         │
│ [ 正文输入区域           ]│
│ [                       ]│
│ [                       ]│
│                         │
│              已保存草稿  │
│ ┌─────────────────────┐ │
│ │       写好了         │ │
│ └─────────────────────┘ │
│ 我需要先叫停              │
└─────────────────────────┘
```

- 不显示情绪和强度，不显示评估入口，不显示字数进度。
- 占位文案只保留一条，输入后消失。
- 草稿状态弱化展示，仅在状态变化时出现，不持续闪烁。
- 正文为空时“写好了”禁用；达到上限时以内联说明提示，不用突然弹窗。
- 关闭时按草稿规则处理；已有正文不直接丢弃。
- 键盘弹出时主按钮保持可达，输入区自动适应，不被底部按钮遮挡。

### 7.3 保存后：可选感受，默认结束

**页面目标**：确认内容已安全保留，并允许用户立即离开。

```text
已经记下
不必现在处理。

此刻的感受（可多选，可跳过）
[ 焦虑 ] [ 烦躁 ] [ 担忧 ] …

强烈程度（可跳过）
[ 2 ] [ 4 ] [ 6 ] [ 8 ] [ 10 ]
未补充时不计入强度统计

[      回到此刻      ]
现在评估
```

- 标题使用“已经记下”，不使用礼花、勋章或“太棒了”。
- 感受区域可以轻量展开；用户不愿补充时不需要点击“跳过”才能结束。
- “回到此刻”为主按钮，“现在评估”为文字或描边次按钮。
- 离线时不显示“现在评估”，显示本机保存状态与后续同步说明。
- 返回首页后只用轻量原位反馈，不再弹第二层成功提示。

### 7.4 处理：突出下一条，而不是展示全部状态

**页面目标**：让用户选择一条思虑继续，不被队列异常淹没。

- 顶部为标题“处理”和页内分段“待处理／已收尾”。
- 本机有待同步或异常时，在标题下显示一行摘要：“3 条仅保存在本机 ›”，点击进入本机登记。
- 待处理列表第一项可作为“下一条”，正文摘要优先，只保留一行辅助信息。
- 单条结构：正文摘要 → 当前步骤或状态 → “继续处理”。
- 不为每条记录同时放置多个按钮，不重复展示版本、强度和全部时间字段。
- 进度仅表示当前所在步骤，不代表疗效或人生进度。
- 空状态为“现在没有待处理的思虑”，提供“去思虑库看看”，不庆祝“全部搞定”。
- 后台刷新保留旧列表；加载失败时保留内容并显示“暂未刷新，可稍后重试”。

### 7.5 思虑库：搜索与内容优先

**页面目标**：快速找到一段内容，并安静阅读历史。

- 顶部搜索框为默认入口，筛选收进一个独立面板。
- 筛选按“状态／情绪／时间／本地内容”分组，不默认展开成芯片墙。
- 已生效条件在搜索框下显示摘要，并提供“清除”。
- 列表顺序：标题或首行 → 正文摘要 → 一行时间与状态。
- 情绪和高频信息按需放入辅助行，不与标题争夺注意力。
- 本地筛选生效时写“已加载内容中显示 6 个”，不能写成“共 6 个”。
- 搜索为空时保留原搜索词和清除入口，不展示与查询无关的推荐内容。

### 7.6 思虑详情：正文优先的版本时间线

- 页面开头展示思虑标题和一条中性复发说明，高频提示只出现一次。
- 默认展开最新版本，其余版本按时间倒序折叠。
- 每个版本内部顺序：正文 → 感受与强度 → 评估内容 → 可执行动作。
- 已收尾版本只读；“再次记录”创建新版本，不修改旧版本。
- 历史版本折叠条只保留版本时间和状态，不重复堆叠所有字段。
- 长评估内容分组展示，避免连续出现大量同级按钮。

### 7.7 七步评估：一步一问

```text
┌─────────────────────────┐
│ 关闭       第 2 步，共 7 步⋯│
│ ────────                │
│                         │
│ 当前问题标题              │
│ 简短说明                  │
│                         │
│ [ 当前步骤输入区域        ]│
│                         │
│ 已暂存                    │
│                         │
│ [       下一步          ] │
│ 上一步        暂存离开    │
└─────────────────────────┘
```

- 顶部步骤定位不重复正文标题。
- 进度条细而短，仅作为位置提示。
- 当前问题、说明和输入是页面主体，示例默认折叠。
- 校验失败在对应字段下方说明，并滚动到首个错误，不仅使用 toast。
- 底部主按钮固定可达；上一步与暂存离开降低层级。
- 搁置、复发相关操作收入更多菜单，但保留明确文字，不使用难理解的图标。
- 收尾前必须展示三项确认，最终动作独立，不能因普通“下一步”误触发。

### 7.8 应急叫停：减少输入，逐拍引导

- 首屏仅三个工具名称和一句适用说明，不展示完成次数。
- 5-4-3 感官落地一次只询问一类感官或一个项目，再进入下一拍。
- 一句打断以大字呈现当前句子，不要求用户先填写表单。
- 5 分钟抽离显示当前剩余时间与暂停／继续；离开页面时按现有能力如实说明。
- 完成页只显示“可以停在这里”与“返回”，不推荐继续打卡或立即记录。

### 7.9 本机登记：可理解、可恢复

- 列表先展示原文摘要和“仅本机／待核对／同步失败／已阻止”等用户语言。
- 详情先展示完整原文，再展示当前状态和下一步。
- `uncertain` 提供“去思虑库核对”直接入口，核对后才允许人工重试。
- `blocked` 说明具体归属变化，不引导用户通过退出登录来“碰碰运气”。
- 技术诊断信息默认折叠；普通流程不显示完整 `clientRequestId`。

### 7.10 我的与隐私：说清数据在哪里

分区顺序：

1. 账号与登录状态；
2. 本机登记；
3. 统计洞察；
4. 数据位置与隐私；
5. 注销与删除。

- 数据位置以只读文字说明“当前使用微信云开发”或“当前使用自有服务器”，不提供前端随意切换器。
- cloud 模式不得写成“微信登录凭证换取 token”；按实际登录机制描述。
- 提醒两套后端数据独立，不承诺自动互通。
- 注销入口使用克制但明确的危险层级，不靠整页红色制造恐慌。

### 7.11 统计洞察：描述，不评价

- 保留现有四项指标、情绪分布与强度趋势。
- 指标用于回顾，不设置目标线、完成率排名或连续天数。
- 无数据与“有记录但未补充强度”分别呈现。
- 不使用默认情绪、默认强度或空数据补出图表。
- 文案避免“状态变好了”等疗效结论，可使用“你记录过这些感受”。

## 8. 组件与交互规范

### 8.1 按钮

| 类型 | 用途 | 规则 |
| --- | --- | --- |
| 主按钮 | 当前页面唯一推进动作 | 每屏至多一个；最小高度 88rpx；首页记录按钮 96rpx |
| 次按钮 | 可选继续或返回上一步 | 描边或浅底，不与主按钮等权重 |
| 文字按钮 | 暂存、稍后、低优先级入口 | 保留足够点击区域，不只让文字本身可点 |
| 危险按钮 | 注销、永久删除 | 只在确认上下文出现，禁用普通危险色装饰 |

状态包括默认、按下、禁用、加载。加载时保持按钮宽度，避免布局跳动；禁用状态仍需满足可读性。

### 8.2 卡片与分组

- 首页不使用多层悬浮卡片。
- 列表默认使用连续表面与细分隔线，只有完整任务项使用浅卡片。
- 阴影极轻或不用；不通过大阴影制造“高级感”。
- 辅助面板不层层嵌套，单页最多两层容器。

### 8.3 标签与选择器

- 情绪标签用于选择，不作为彩色分类装饰。
- 选中态使用灰绿浅底与深色文字，不仅依靠颜色，同时提供勾选或边框变化。
- 强度选择保持同一行或均匀换行，未选择就是未补充，不默认给中间值。

### 8.4 提示与反馈

- **toast**：仅用于短暂、无后续动作的事实反馈，如“已复制”。
- **原位状态**：保存、同步、字段错误和局部刷新，优先在发生位置反馈。
- **内联横幅**：需要持续可见且可恢复的异常，附一个明确动作。
- **弹窗**：仅用于不可逆操作或必须由用户决定的关联，不用于普通成功提示。
- **空页面**：解释当前状态，并给一个真正有用的下一步。

### 8.5 动效

- 页面与控件状态过渡 180–240ms。
- 按下反馈以轻微透明度或底色变化为主，不使用夸张弹跳。
- 保存成功不使用全屏庆祝动画。
- 支持系统减少动态效果偏好；关闭非必要位移和缩放。
- 加载超过可感知等待时使用骨架或状态文字，不让旧内容突然闪空。

## 9. 视觉设计令牌

整体沿用暖白、墨色和灰绿。参考稿提供秩序与色彩方向，止念保留更深的品牌灰绿作为动作色。

### 9.1 色彩

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| `color.bg.page` | `#F7F6F2` | 页面背景 |
| `color.bg.surface` | `#FCFCFA` | 输入区、任务表面 |
| `color.bg.subtle` | `#E9ECE5` | 浅灰绿选中底、分组底 |
| `color.text.primary` | `#242824` | 标题与正文 |
| `color.text.secondary` | `#656D63` | 辅助说明与元信息 |
| `color.action.primary` | `#385C57` | 主按钮、关键选中态 |
| `color.action.pressed` | `#2E4B47` | 按下状态 |
| `color.border.default` | `#E3E3DD` | 细线与描边 |
| `color.state.error` | `#A34D42` | 错误文字与必要危险操作 |
| `color.state.warning` | `#8B6B35` | 待核对、非破坏性提醒 |

规则：

- 不使用纯黑大标题、纯白高亮卡片和大面积高饱和色。
- 不用红色表达普通待办；红色只用于错误和不可逆风险。
- 成功状态沿用品牌灰绿，不额外制造鲜亮“成就绿”。
- 正文和辅助文字对背景的对比度按 WCAG AA 校验；状态不只靠颜色区分。

### 9.2 字体与行高

| 层级 | 建议字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 40rpx | 600 | 页面唯一主标题 |
| 分组标题 | 32rpx | 600 | 评估问题、详情分组 |
| 正文 | 28rpx | 400 | 输入与阅读正文 |
| 辅助信息 | 24rpx | 400 | 时间、状态、说明 |
| 极小文字 | 不低于 22rpx | 400 | 仅非关键短信息，避免连续正文 |

- 正文行高 1.55–1.7，辅助文字行高不低于 1.4。
- 不复制参考稿手机稿中过小的文字。
- 长正文左对齐，不使用居中大段阅读。
- 数字使用等宽数字特性（环境支持时），避免计时和统计跳动。

### 9.3 间距、圆角与触控

- 页面左右安全留白 32rpx。
- 以 8rpx 为基础间距单位，常用间距 8／16／24／32／40／48rpx。
- 页面主分组间距 40–48rpx，组内间距 16–24rpx。
- 输入区与按钮圆角 12rpx，独立表面可用 16rpx；不使用过多胶囊形容器。
- 主要触控目标高度不低于 88rpx；图标按钮可点区域不低于 64rpx，并优先达到 88rpx。
- 细线以 1px 物理像素实现，避免不同设备上过粗。
- 适配底部安全区与键盘，主按钮不得被遮挡。

## 10. 微文案规范

### 10.1 语言风格

- 短句、具体、不命令、不评判。
- 描述发生了什么，不承诺情绪或疗效。
- 不使用“坚持”“失败”“漏做”“战胜”“搞定一切”等压力语言。
- 不用“云端安全无忧”等绝对化隐私承诺。

### 10.2 核心文案表

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 首页主标题 | 把念头先放在这里。 | 今日也要坚持记录 |
| 首页补充 | 不需要现在想明白。 | 立即完成今日任务 |
| 书写占位 | 此刻在想什么？写下来就好。 | 请完整描述你的问题 |
| 保存成功 | 已经记下。 | 太棒了，又完成一次！ |
| 保存后引导 | 可以补充感受，也可以回到此刻。 | 请继续完成全部信息 |
| 待处理为空 | 现在没有待处理的思虑。 | 全部搞定，你赢了 |
| 离线保存 | 已保存在本机，联网后可同步。 | 保存成功 |
| 结果待核对 | 上次结果还不确定，请先到思虑库核对。 | 网络错误，请重试 |
| 同步失败 | 尚未同步，原文仍在本机。 | 操作失败 |
| 应急完成 | 可以停在这里。 | 恭喜你完成叫停 |
| 删除失败 | 云端数据尚未确认删除，本机内容已保留。 | 删除失败，请稍后再试 |

## 11. 状态与异常设计

| 场景 | 页面表现 | 主行动作 | 数据承诺 |
| --- | --- | --- | --- |
| 首次使用 | 保留记录入口，隐藏无意义统计 | 记录思虑 | 不制造示例数据 |
| 正文为空 | 主按钮禁用 | 输入正文 | 不提交空记录 |
| 匹配中 | 保留正文，显示匹配状态 | 等待或按现有规则继续 | 不重复创建 |
| 匹配失败 | 内联说明检查未完成 | 保存为新思虑 | 正文保留 |
| 保存中 | 按钮加载，防重复提交 | 等待 | 沿用幂等标识 |
| 离线保存 | 明确“仅本机” | 回到此刻 | 不声称云端成功 |
| 后台刷新 | 保留旧内容，局部状态提示 | 继续阅读 | 不清空列表 |
| 刷新失败 | 内联提示，不遮挡内容 | 重试 | 旧内容仍可看 |
| 评估同步失败 | 当前字段下或底部持续提示 | 留在页面或稍后重试 | 本机暂存保留 |
| 结果不确定 | 本机登记显示待核对 | 去思虑库核对 | 不自动重发 |
| 后端／账号变化 | 显示阻止原因 | 查看原文与归属说明 | 不跨后端重放 |
| 注销失败 | 确认层持续显示错误 | 稍后人工重试或退出 | 会话与本机内容保留 |
| 无统计强度 | 显示“尚未补充强度” | 返回记录或思虑库 | 不按 0 计算 |

## 12. 无障碍与安全

- 文字和关键图标满足对比度要求；选中、错误和成功不只靠颜色。
- 所有图标按钮提供可读标签，如“关闭记录”“更多评估操作”。
- 动态字体放大时，正文与按钮文字可换行，不截断核心动作。
- 输入框有持久可理解的用途说明，不能只依赖占位文字。
- 校验错误与字段建立语义关联，屏幕阅读器能理解错误位置。
- 触控目标符合最小尺寸，相邻危险操作保持足够距离。
- 动画遵循减少动态效果偏好，计时工具不依赖动画才能理解。
- 应急入口不依赖登录、网络或已有数据。
- 应急页面不暗示专业救援；如保留外部求助信息，必须基于可靠来源并单独审核，不在本次视觉改版中新增医疗承诺。

## 13. 实施范围与顺序

### P0：先完成核心闭环

1. **基础令牌与组件**：颜色、字体、间距、按钮、分组、反馈、空状态。
2. **此刻与速记**：首页唯一主入口；全屏正文；相似确认；保存后感受；默认回到此刻。
3. **处理与七步评估**：下一条优先；异常摘要；步骤页动作降层级；错误原位反馈。
4. **思虑库与详情**：搜索筛选收敛；内容优先列表；最新版本展开的时间线。
5. **应急、本机登记、我的与注销**：完整保留安全与恢复能力，统一新视觉语言。
6. **统计洞察**：改为解释性回顾，不出现成就化表达。

### P1：高保真验证后增强

- 更细致的空状态插画或纹理，仅在不妨碍正文时使用。
- 键盘、长文本、字体放大和减少动态效果的进一步适配。
- 列表刷新与版本展开的细微过渡。
- 真机触控、屏幕阅读器与不同尺寸设备调优。

### 不在本次范围

- 新增打卡、日历、补签、勋章、提醒或社交功能。
- 修改七步问题、数据模型、接口字段、同步算法或账号体系。
- 在 cloud 与 HTTP 之间迁移、同步或合并数据。
- 新增医疗建议、诊断或疗效预测。

## 14. 验收标准

### 14.1 首页与记录

- [ ] 首页首屏只有“记录思虑”一个实心主按钮。
- [ ] 今日登记与待处理只占轻量摘要，不形成第二个视觉中心。
- [ ] 应急入口始终可达，但视觉上低于记录入口。
- [ ] 书写第一阶段没有情绪、强度、统计、字数或评估字段。
- [ ] 输入、键盘、草稿和关闭流程不会丢失未提交正文。
- [ ] 相似候选不展示相似度百分比，不自动关联。
- [ ] 保存后可以不选择任何感受直接回到此刻。
- [ ] “回到此刻”为默认主动作，“现在评估”为次动作。
- [ ] 离线保存不显示“现在评估”，且明确数据只在本机。

### 14.2 处理与思虑库

- [ ] 处理页异常以摘要出现，不压过待处理内容。
- [ ] 单条记录正文优先，辅助状态不超过一行。
- [ ] 七步评估每屏只有当前问题，下一步为唯一主按钮。
- [ ] 上一步、暂存离开、搁置和恢复均符合原业务规则。
- [ ] 已收尾只读，复发创建新版本，旧版本不被覆盖。
- [ ] 思虑库筛选默认收起，生效条件可查看、可清除。
- [ ] 本地筛选结果明确写“已加载内容中显示 X 个”。
- [ ] 详情默认展开最新版本，历史版本时间线可折叠。

### 14.3 异常、隐私与应急

- [ ] 每个错误都说明内容是否保留、当前状态和下一步。
- [ ] `uncertain` 有“去思虑库核对”路径，不直接自动重发。
- [ ] 普通用户界面不展示完整技术幂等标识。
- [ ] cloud 与 HTTP 的数据位置和登录说明准确，不混用文案。
- [ ] 注销只有服务端确认成功后才清空本机数据。
- [ ] 应急无需登录和网络，不生成记录，不覆盖草稿，可随时退出。

### 14.4 视觉与可用性

- [ ] 使用统一色彩、字体、间距和圆角令牌，无页面私有随机色。
- [ ] 主要触控目标不小于 88rpx，按钮不被键盘或安全区遮挡。
- [ ] 长正文、长标题、空数据、200% 字体和减少动态效果模式可用。
- [ ] 无红点催收、连续天数、勋章、排名或完成庆祝。
- [ ] 成功、空、加载和失败状态在同一页面结构中连续呈现。
- [ ] 至少完成一次微信开发者工具编译和一轮真机核心流程验证后，才认定视觉实施完成。
