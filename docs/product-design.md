# 「止念」产品与交互设计

> 项目：`mind_trace`。本文以当前代码为产品基线，说明已实现的用户角色、场景、页面、状态和 V1 边界；接口字段与部署步骤不在此展开。
>
> 「止念」是随身思虑登记与结构化处理工具，不是日记、医疗诊断、心理治疗或紧急救援服务。

## 1. 产品目标与原则

### 1.1 核心目标

帮助用户在念头反复出现时，先用低负担方式登记，再在相对平静时完成结构化处理：

1. **先书写，后补充**：第一步只写思虑正文；保存后再选择是否补充情绪和强度，不要求当场想通。
2. **一次只处理一步**：七步评估分屏呈现，可暂存、退出或搁置。
3. **复发不覆盖历史**：同一主题可关联多个独立版本，每版重新评估和收尾。
4. **先照顾当下**：应急工具不依赖账户、网络或思虑记录。
5. **数据由用户决定**：提供注销删除，并明确本机草稿和待同步内容的处理方式。

### 1.2 低刺激与高级简洁原则

- 使用暖白背景 `#F7F7F4`、墨色正文 `#202522` 和单一灰绿强调色 `#385C57`；不以渐变、阴影、玻璃拟态或插画制造“高级感”。
- 以系统字体、三级字级、稳定留白和细分隔线建立层级；列表优先连续排版，减少卡片套卡片和过大圆角。
- 每个页面突出一个主要任务；书写阶段移除所有非必要表单、字数和统计，不设置签到、红点催收或失败惩罚。
- 提示而非评判：相似思虑只由用户确认关联；“高频”仅表示版本数达到 3，不代表疾病或人格特征。
- 动画服务于反馈，不使用连续庆祝、强闪烁或自动播放声音；输入和步骤优先于装饰，主要触控目标不小于 88rpx。
- 错误说明发生了什么、内容是否保留、下一步能做什么，不用“成功”掩盖网络失败。
- 不索取通讯录、位置等无关权限，不强制填写昵称或头像。
- 若用户存在即时人身安全风险，应优先联系可信赖的人或当地紧急服务，而不是继续使用评估流程。

## 2. 用户角色与使用场景

### 2.1 角色

| 角色 | 使用端 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 微信用户 | 原生小程序 | 管理自己的思虑、版本、评估、统计和本机待同步内容；使用应急工具；注销账号 | 读取其他用户数据；选择数据归属用户；直接访问管理接口 |
| 运营管理员 | Vue 管理端，仅 HTTP 模式 | 登录后查看聚合概览及用户 ID、昵称、注册时间、思虑数、记录数 | 查看思虑正文；访问 cloud 数据；在 V1 修改或删除用户 |
| 应急工具使用者 | 小程序“应急叫停” | 离线进行感官落地、一句打断和 5 分钟抽离 | 被当作医疗或紧急救援服务对象；自动向他人发送求助信息 |

### 2.2 典型场景

- **随时登记**：工作汇报前突然担心出错，先只写下脑海中的原话；正文保存后再决定是否补充情绪与强度，也可以直接回到当下。
- **空闲评估**：晚间从“处理”打开待办，逐步区分风险、概率、可控行动和不可控内容，再确认收尾。
- **复发复盘**：再次出现相似念头时，主动关联旧思虑点；查看 v1、v2 等版本，保留每次独立处理结果。
- **弱网或离线**：速记网络失败时保存到本机；恢复网络后只自动发送明确处于 `queued` 且账号、后端一致的内容，结果不确定时由用户核对后重试。
- **需要立即抽离**：不登记、不登录，直接进入应急叫停，将注意力带回感官或暂离当前环境。
- **注销删除**：在“我的”中输入指定文字，删除当前用户服务端数据并清空本机敏感数据。

## 3. 信息架构与核心对象

### 3.1 小程序页面

底部三个 Tab 为“此刻”“处理”“思虑库”；其余页面通过导航进入。

| 页面 | 路径 | 当前主要能力 |
|---|---|---|
| 此刻 | `pages/now/index` | 打开速记；查看今日登记和待处理数；进入“我的”、处理队列和应急叫停 |
| 处理 | `pages/process/index` | 查看待处理／已收尾版本；显示本机待同步列表并触发队列检查 |
| 思虑库 | `pages/library/index` | 搜索、状态与情绪筛选、分页加载；对已加载内容按时间和高频条件过滤；进入统计 |
| 七步评估 | `pages/evaluate/index` | 新建或恢复评估；本机暂存与服务端同步；搁置、只读回看和收尾 |
| 思虑详情 | `pages/thought-detail/index` | 查看思虑点及倒序版本时间线，展开单版内容或继续评估 |
| 本机登记 | `pages/local-record/index` | 查看尚未同步的正文、归属与同步状态；人工重试或删除本机副本 |
| 应急叫停 | `pages/emergency/index` | 5-4-3 感官、一句打断、5 分钟抽离 |
| 统计洞察 | `pages/stats/index` | 数量、完成率、高频主题、情绪分布和近 30 天强度趋势 |
| 我的 | `pages/profile/index` | 当前账号、统计与待同步入口、隐私说明、注销删除 |

“我的”不是第四个 Tab，从“此刻”右上角进入。“统计”可从“思虑库”或“我的”进入。

### 3.2 核心对象

- **思虑点 Thought**：长期主题，包含多个登记版本。状态为 `active`（活跃）、`resolved`（已完结）、`recurring`（反复）。
- **登记版本 Record**：一次具体登记及一次独立评估。状态为 `registered`（待评估）、`evaluating`（评估中）、`paused`（已搁置）、`closed`（已收尾）。
- **复发关联**：用户确认后向已有思虑点增加版本。新版本继承上一版评估字段，但 `step` 从 0 开始，三项收尾确认重置。
- **本机待同步项**：尚未确认写入服务端的速记，包含正文、幂等标识、原账号、原后端环境和同步状态；不是服务端记录。
- **思虑点状态规则**：版本数达到 3 后为 `recurring`；少于 3 版且没有未收尾版本时为 `resolved`；其余为 `active`。达到 3 版的历史状态不会因全部收尾而退化为 `resolved`。

应急叫停不生成记录，不新增“已叫停”状态，也不覆盖速记或评估草稿。

## 4. 核心流程

### 4.1 启动与登录

1. 小程序启动后恢复中断的离线队列状态，并在后台确保登录；页面请求前也会再次确保登录。
2. 默认 cloud 模式由云函数根据微信上下文识别用户，不调用 `wx.login`，不向用户展示额外登录按钮；HTTP 模式使用 `wx.login` 临时凭证换取 token。
3. 登录成功后，小程序核对缓存用户与离线记录归属，再检查可自动同步的项目。
4. 登录失败不反复弹窗；页面显示错误或重试状态，本机未同步内容不被自动删除。
5. 云模式的公开用户 ID 包含用户代次。注销后重新登录会得到不同代次，旧账号待同步内容被阻止写入新账号。

### 4.2 聚焦书写与记录后补充

1. 在“此刻”点击“记录思虑”，进入全屏书写界面。第一步只显示思虑正文输入和“写好了”，不展示触发事件、情绪、强度、字数或统计，避免分散输入注意力。
2. 正文为 1–1000 字，引导用户直接写下脑海中的原话。系统内部取首个非空行的前 100 字作为 `triggerEvent` 短标题，完整正文始终保存为 `loopThought`，无需用户重复填写。
3. 未提交正文即时保存为本机速记草稿，重新打开组件时恢复；空白正文不能提交。
4. 提交后先检查相似思虑。命中候选时，用户选择“关联为新版本”或“作为新思虑保存”；没有候选时直接创建。匹配只使用单正文，避免拼接重复文本。
5. 相似检查发生非网络业务错误时，允许返回修改或作为新思虑继续；发生网络错误时将本次内容保存到本机队列。首次创建固定 `emotions=[]`、`intensity=null`，不伪造默认感受。
6. 正文创建或入队后进入第二步“补充感受”：情绪可多选，强度以“很轻／较轻／明显／较强／很强”对应 2／4／6／8／10。两项都可留空，选择“暂不补充”不会阻断记录。
7. 在线记录通过 `PATCH /records/:id` 保存补充信息；离线记录仅在仍为 `queued` 时更新本机待发送 payload，保持同一 `clientRequestId`。若已 `sending/uncertain`，不覆盖待确认内容，提示稍后再补充。
8. 补充完成后提供“现在评估”“回到此刻”“我需要先叫停”。本机保存成功时不提供“现在评估”，须先同步取得服务端记录。未补充强度在列表和详情中明确显示“未补充”，且不进入平均强度统计。
9. 关联复发时，新记录从待评估状态开始；旧版本保留，上一版的评估内容作为本次可修改的初始值。

每次创建生成并保留 `clientRequestId`。相同登记的核对后重试沿用该键，由服务端幂等约束避免重复版本；匹配分数本身不会触发自动关联或合并。

### 4.3 处理队列与本机待同步

- “处理”读取第一页最多 100 条服务端记录，并分为：
  - **待处理**：所有非 `closed` 版本，按强度从高到低排列；
  - **已收尾**：`closed` 版本，按收尾或更新时间倒序排列。
- 连续列表显示版本号、正文摘要、状态、强度、更新时间和当前步骤；短标题与正文相同时不重复展示。未补充强度明确标注，待处理可继续评估，已收尾只读。
- 本机队列独立显示在页面上方，可查看原文和状态、检查队列、人工同步或删除本机副本。
- 只有 `queued` 且归属完整一致的项目自动发送；`sending` 在启动恢复时变为 `uncertain`。
- `failed`、`uncertain`、`blocked` 不盲目自动重发。`uncertain` 人工重试前提示先到思虑库核对，并沿用同一幂等键。
- 账号、用户代次、cloud 环境或 HTTP API 地址变化，以及旧记录缺少归属字段时，项目标记为 `blocked`，内容仍保留在本机。

### 4.4 七步评估与草稿

| 步骤 | 用户任务 | 进入下一步／收尾条件 |
|---|---|---|
| 1 判断 | 选择“有效推演”或“无效反刍” | 必须选择 `ruminationType` |
| 2 风险 | 写具体担心什么会出错 | `riskContent` 非空 |
| 3 概率 | 用滑杆填写 0–100% | 数值在范围内；低于 20% 只显示温和提示 |
| 4 可控行动 | 每行一项，可逐项勾选完成 | 至少一项 `controllableActions` |
| 5 不可控 | 每行一项，可逐项“划掉” | 至少一项 `uncontrollableItems` |
| 6 三种视角 | 填写最坏、最可能、最好 | 三项均非空 |
| 7 三项确认 | 确认已写可控行动、已划掉不可控项、继续思考不再增加收益 | 三项均为真 |

- 每次编辑立即暂存本机，1.4 秒无新编辑后同步服务端；页面隐藏时也尝试保存。
- 服务端保存成功才删除对应本机草稿；失败保留本机内容并显示“暂存本机”或“离线草稿已保存在本机”。
- 重新进入时优先恢复可用本机草稿；无网络但有草稿时可继续填写。草稿不是离线新建服务端记录的替代品。
- “暂存并离开”保留当前步骤；“暂时搁置”先保存草稿，再调用搁置接口。
- 收尾前客户端逐步检查全部七步，再保存第 7 步并调用专门收尾接口；服务端再次校验，不能通过普通草稿保存直接改成 `closed`。
- 已收尾版本只读，不允许继续编辑、搁置或重复收尾。
- 收尾成功后显示 3 秒呼吸反馈，再提供返回处理队列和去思虑库；当前实现没有单独的“跳过动画”按钮。

### 4.5 思虑库、详情与统计

1. 关键词、思虑状态和情绪由服务端接口筛选；分页默认每页 20 条，可继续加载。
2. 关键词覆盖思虑主题以及版本的触发事件、循环念头和风险内容。
3. “近 7／30／90 天”和“只看高频思绪”在当前已加载列表上过滤，不是独立服务端查询；结果计数显示筛选后可见数量。
4. 详情按版本号倒序展开，展示登记正文、评估答案、状态和时间，可继续未收尾版本或查看已收尾结果。
5. 统计展示思虑点数、登记版本数、完成率、高频主题数、思虑点最新情绪分布和近 30 天有记录日期的平均强度。
6. 没有登记时显示空态；没有趋势时不伪造数据。统计用于自我观察，不构成诊断或疗效结论。

### 4.6 应急叫停

无需网络、登录或已有记录，包含三种本地工具：

- **5-4-3 感官**：依次填写看见的 5 样东西、听见的 4 种声音、触碰的 3 个物体；当前步骤填写完整才进入下一步，可返回上一步或完成后重做。
- **一句打断**：复述“这是想法，不是事实”，仅提供当次反馈和轻震动，不形成打卡。
- **5 分钟抽离**：提示离开当前位置；可开始、暂停、继续和重置。以本机结束时间恢复计时，页面隐藏时停止界面 ticker，不承诺后台精确唤醒；完成时震动，无自动声音。

工具不自动写入思虑库，退出返回进入前页面。

### 4.7 注销与删除

1. 在“我的”查看删除范围，并先确认本机登记已同步。
2. 输入“删除全部数据”后才能执行；操作不可撤销。
3. 默认 cloud 模式执行可重入的分阶段清理；HTTP 模式在事务中删除当前用户业务数据。
4. 只有服务端成功后才显示“全部数据已删除”，随后清空本地身份、草稿、离线队列和其他 storage，并增加删除代次使已挂载速记组件失去旧敏感状态。
5. 删除失败保留当前会话和重试入口，不提前清空本地数据。

## 5. 页面状态与异常反馈

| 页面／组件 | 加载与空态 | 异常和恢复 |
|---|---|---|
| 此刻 | 加载今日和待处理计数；无待办时不显示处理快捷入口 | 首页统计失败显示重试；速记和应急入口仍可使用 |
| 速记 | 单正文编辑、匹配中、候选确认、保存中、补充感受、完成分阶段显示 | 正文错误就地提示；网络失败存本机；补充失败不影响已记录正文； queued 之外的本机项不覆盖 |
| 处理 | 待处理／已收尾各自空态；本机队列单独显示 | 保留本机条目，显示失败、待确认或阻止原因；可进入详情处理 |
| 七步评估 | 显示步骤进度、暂存和同步状态 | 保存失败保留草稿；关闭失败定位缺项；已收尾改只读 |
| 思虑库 | 加载、无相符结果和加载更多状态 | 查询失败保留筛选条件并提供重试 |
| 思虑详情 | 加载版本时间线 | 无权限或已删除时显示错误，不借用其他用户缓存 |
| 统计 | 无记录、无情绪或无趋势分别显示空态 | 接口失败显示错误，不用 0 冒充成功统计 |
| 应急 | 立即可用，无远程空态 | 不依赖接口；计时可暂停、重置或退出 |
| 我的／注销 | 登录失败时可显示本机缓存账号和错误 | 删除未确认成功前不清空本地数据 |

通用反馈不暴露服务端堆栈或秘密。网络失败、权限失效、校验失败和同步成功必须可区分。

## 6. 双模式对用户的实际影响

| 项目 | cloud（默认） | http（保留） |
|---|---|---|
| 数据位置 | 当前微信云开发环境 | `API_BASE` 对应的 Go API 与 MySQL |
| 登录 | 云函数从微信上下文识别，含用户代次 | `wx.login` 换取 JWT |
| 管理端 | V1 不互通 | Vue 管理端可看聚合数据和用户计数 |
| 部署感知 | 不需自建 API 域名及 `request` 合法域名 | 需要 HTTPS API 和合法域名配置 |
| 页面流程 | 与其他模式一致 | 与其他模式一致 |

**两种模式的数据不自动同步。** 切换配置只是切换后端，不是迁移、合并或去重；同一微信用户可能看到另一套数据。离线记录会绑定原模式及环境，禁止跨后端自动重放。云套餐、额度及审核要求以平台当期规则为准。

## 7. V1 明确不包含

- 不做医疗诊断、心理治疗、疗效判断、危机识别或紧急救援调度。
- 不提供自动关联、自动或手动合并思虑点、跨思虑点移动版本。
- 不提供云模式与 HTTP 模式之间的数据同步、迁移或统一账号映射。
- 不提供 cloud 数据的 Vue 管理端；管理端也不查看正文或编辑用户数据。
- 不提供多设备本机草稿实时同步、离线完成七步后直接离线收尾、跨设备冲突解决。
- 不提供完整的离线思虑库；列表和详情依赖服务端，本机只保存指定草稿与待同步速记。
- 不提供社交分享、公开社区、连续签到、主动催收或复发推送。
- 不提供独立隐私政策页面、消息通知、语音输入、图片附件、数据导出或备份恢复界面。
- 不保证所有弱网请求都能自动判定最终结果；不确定结果需要用户核对。

## 8. V1 可验证验收

1. **登记**：第一步仅有正文输入，空白或超长正文被阻止；保存后才能补充情绪与强度，可跳过且空强度显示“未补充”并排除于均值；未提交草稿重进可恢复。
2. **复发**：相似候选只提示；用户确认关联后版本号递增、旧版本不变、评估字段继承且三项确认重置。
3. **评估**：七步逐项校验；编辑后本机暂存；服务端成功后草稿清除；中途离开可恢复；已收尾版本只读。
4. **收尾**：任一必填项或确认缺失均不能关闭；成功后版本为 `closed`、`step=7`，思虑点状态按版本数和未收尾数更新。
5. **队列与筛选**：待处理／已收尾分组正确；服务端关键词、状态、情绪筛选和分页正确；本机时间／高频筛选只影响已加载项目。
6. **离线**：网络失败生成本机项；联网只自动发送合法 `queued` 项；中断项恢复为 `uncertain`，不会自动重发。
7. **归属**：账号、代次、模式或环境变化时本机记录被阻止同步且原文保留；同一用户、同一后端才可继续。
8. **幂等**：人工核对后沿用相同 `clientRequestId` 重试，只保留首次登记及版本。
9. **应急**：断网可使用三种工具；感官步骤、计时暂停恢复及退出可用；不写服务端记录。
10. **注销**：未输入指定文字不能删除；失败不清本机数据；成功后本机敏感数据清空，旧身份不能读取或写入新代次数据。
11. **管理端（HTTP）**：管理员可登录、查看概览和用户分页；401 返回登录；用户 token 不可访问管理接口；响应中不含思虑正文。
12. **双模式**：相同业务流程在两种模式分别通过；切换后端后不会误把旧离线记录写入新环境。

功能路径对应接口以 [cloud-api](./cloud-api.md) 和 [api-contract](./api-contract.md) 为准；组件、状态存储和时序见 [code-design](./code-design.md)；发布验收另见 [release-checklist](./release-checklist.md)。
