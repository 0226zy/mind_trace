# 「止念」产品与交互设计

> 项目名：`mind_trace`  
> 产品定位：随身思虑登记与结构化处理工具，不是日记、医疗诊断或心理治疗服务。  
> V1 范围：微信原生小程序；默认 cloud 契约见 [cloud-api](./cloud-api.md)，可选 HTTP 契约见 [api-contract](./api-contract.md)。

## 1. 设计原则

1. **先登记，后处理**：情绪强烈时只记录触发事件、情绪与循环念头，不要求立即分析。
2. **低刺激、低负担**：米白/雾蓝等低饱和色；无红点轰炸、无强闪烁、无连续庆祝动效；首屏主行动只有一个。
3. **一步一屏，随时可退**：七步评估分屏呈现，自动暂存，允许搁置；返回不会清空输入。
4. **提示而非评判**：相似思虑只提示，不自动合并；“高频”用于观察模式，不贴病理化标签。
5. **隐私可见**：登录、同步、失败、删除均使用明确文案；不索取通讯录、位置等无关权限。
6. **工具不替代求助**：若用户存在即时人身安全风险，应优先联系可信赖的人或当地紧急服务，而非继续使用评估流程。

## 2. 信息架构

### 2.1 小程序

底部三个 Tab：

- **此刻**：默认首页；主按钮“我陷入了一个思虑”；应急叫停常驻入口；今日登记数、待处理数与入口。
- **处理**：待评估、评估中、已搁置、已收尾队列；显示版本进度并恢复草稿。
- **思虑库**：思虑点列表、关键词搜索、状态/情绪筛选、统计入口、版本时间线。

全局或“我的”入口：当前账号、隐私协议、数据说明、注销并删除全部业务数据。

### 2.2 核心对象

- **思虑点 Thought**：长期主题，可包含多次登记。
- **登记版本 Record**：一次具体陷入及一次独立评估；归属一个思虑点。
- **复发**：为已有思虑点新增版本；旧版本保留，新版本可继承上一版评估字段后继续修改。
- **版本状态**：`registered`（已登记）、`evaluating`（评估中）、`paused`（已搁置）、`closed`（已收尾）。
- **思虑点状态**：`active`、`resolved`、`recurring`；列表同时展示版本计数、最近记录与当前进度。

> 应急叫停是独立工具，不新增“已叫停”版本状态，也不打断或覆盖评估草稿。

### 2.3 数据模式说明

- **默认 `DATA_MODE=cloud`**：小程序通过云函数 `mindTrace` 使用微信云开发，身份由云函数 `OPENID` 确定，数据保存在 `users / thoughts / records` 集合，普通归属字段为 `ownerOpenid`；页面不直接读写数据库。登录不传 `code`，公开用户 ID 为 `${_id}:${generation}`，非 login 调用携带 `actorUserId` 校验用户代次。
- **保留 `DATA_MODE=http`**：小程序通过 Go API 使用 `code` 登录并保存 JWT，数据保存在 MySQL；Vue 管理端仅支持此模式。cloud 模式 V1 无管理端数据互通。
- 两套数据**不自动同步**。切换模式不是迁移，用户可能看到另一套记录；每条离线队列绑定 `ownerUserId + backendMode + backendEnv`，账号/代次或后端变化时阻断自动同步并保留本机数据。
- 本文中的 HTTP 路径用于表达产品能力；cloud 模式由请求层映射为 [cloud-api](./cloud-api.md) 中对应 action，页面流程、字段和状态不变。
- cloud 不需要自建 API 域名、该域名 ICP备案或 `request` 合法域名，但仍需完成小程序主体注册、隐私、类目、体验版与审核。云套餐和免费额度以控制台当期为准，不向用户承诺固定免费。

## 3. 完整产品流程

### 3.1 首次进入与微信登录

1. 展示一句产品说明与隐私协议入口，不播放强制引导。
2. 用户主动点击“微信登录”：默认 cloud 调用 `mindTrace` 的 `login`，由云函数通过 `OPENID` 查找或创建用户；HTTP 模式取得临时 `code` 并调用 `POST /auth/wechat/login`。
3. 登录成功后进入“此刻”；cloud 保存 `${_id}:${generation}` 复合用户 ID，后续非 login 调用作为 `actorUserId` 携带，HTTP 保存 JWT。昵称、头像为可选资料。
4. 登录失败时保留本地未同步内容，提供“重试”和“暂存本机”；不循环弹窗。
5. 身份失效、代次不符或用户不存在时，敏感页面不继续展示明文缓存；重新登录后核对新用户 ID 再恢复同步，避免旧代次请求写入注销后的新账号。

### 3.2 30 秒快速登记

1. 点击首页主按钮，打开半屏速记面板。
2. 填写三个必填部分：
   - 触发事件：1–100 字；
   - 情绪标签：多选，强度 1–10；
   - 循环念头：1–1000 字，引导语“原话写下，不加修饰”。
3. 提交前可用触发事件与循环念头调用 `POST /thoughts/match` 检查相似主题；弱网不因此阻断登记。
4. 若有候选，展示历史主题、复发次数和最近时间，由用户选择：
   - **关联为新版本**：提交 `POST /records` 时携带 `thoughtId`；
   - **作为新思虑**：不携带 `thoughtId`。
5. 服务端创建记录；有关联时新增版本并继承上一版评估字段。
6. 成功反馈：“已记录。大脑可以暂时放下它了。”提供“稍后处理”“现在评估”“我需要先叫停”。

约束：匹配结果永远只提示；不因高分自动关联，不在 V1 提供自动或手动合并思虑点流程。

### 3.3 待处理与草稿恢复

- “处理”页通过 `GET /records` 分页读取，可按版本状态筛选。
- 卡片显示主题摘要、最近登记时间、强度和“第 n / 7 步”。
- 点击已登记版本进入第 1 步；评估中版本回到 `step`；已搁置版本可继续评估；已收尾版本只读回看。
- 每步保存使用 `PATCH /records/:id`；离开、切后台或断网前保留本地草稿。
- “暂不处理”调用 `POST /records/:id/pause`，不删除任何内容。

### 3.4 七步评估

| 步骤 | 标题与输入 | 交互及通过条件 |
|---|---|---|
| 1 | **有效推演还是无效反刍？** | 二选一 `ruminationType`；辅助问“这是第几遍想？有没有新信息？” |
| 2 | **具体担心什么会出错？** | 填写 `riskContent`，聚焦可描述的事件，不要求积极思考。 |
| 3 | **发生概率是多少？** | `probability` 0–100；低于 20% 仅显示温和“低概率”提示，不自动改值。 |
| 4 | **哪些部分可以补救？** | `controllableActions[]` 为 `{text, done}`；支持增删、完成勾选，行动写到可执行粒度。 |
| 5 | **哪些部分超出控制？** | `uncontrollableItems[]` 为 `{text, crossedOut}`；逐条点击“划掉”，以删除线和淡出表达，不使用惩罚性动画。 |
| 6 | **换三个视角看这件事** | 分别填写最坏、最可能、最好：`scenarioWorst / scenarioLikely / scenarioBest`；缺一不能收尾。 |
| 7 | **确认并收尾** | 三项 `closeConfirmations`：已处理可控行动、已划掉不可控项、继续思考不再增加收益；三项均确认后点击“此刻结束，回到当下”。 |

收尾调用 `POST /records/:id/close`。服务端再次校验必填项和三项确认；客户端不绕过校验。成功后状态为 `closed`，展示可跳过的 3 秒平静动画，并提供“返回此刻”“查看记录”。若校验失败，保留输入并定位到对应步骤。

### 3.5 检索、详情与统计

1. 思虑库使用 `GET /thoughts` 的 `query / status / emotion / page / pageSize` 检索与分页。
2. 空关键词时展示最近主题；输入后展示匹配主题，不高亮成刺眼色块。
3. 详情通过 `GET /thoughts/:id` 展示思虑点和倒序版本时间线；每个版本可查看登记内容、七步答案、状态与收尾结果。
4. 统计页通过 `GET /stats/summary` 展示思虑点数、登记数、收尾数、完成率、高频主题数、情绪分布和强度趋势。
5. 统计只描述记录，不给出疾病、人格或疗效判断；样本过少时提示“记录还很少，暂不做趋势解读”。

### 3.6 复发关联与版本继承

- 登记时命中相似主题，文案示例：“这个主题之前登记过 2 次，要作为它的新版本吗？”
- 用户确认后才携带 `thoughtId`；服务端新增版本并继承上一版评估字段。
- 新版本仍是独立流程：初始为 `registered`，需重新逐步确认并独立收尾，旧版本不被覆盖。
- 预填内容显示“来自上一版，可修改”；避免让用户误以为已经处理完。
- 时间线呈现 v1、v2、v3 及各自结论；复发计数等于版本数，高频状态不自动发送提醒。

### 3.7 应急叫停

入口常驻“此刻”，登记成功页也可进入；断网可用，不强制登录、不要求先填记录。

1. **感官落地**：依次提示看到 5 样东西、听到 4 种声音、触摸 3 个物体；可勾选或输入，可跳过任一项。
2. **一句打断**：大字号显示“这是想法，不是事实”；点击“我复述过了”仅作当次反馈，不制造打卡压力。
3. **物理抽离**：可启停的 5 分钟计时，提示起身、喝水或走到安全处；默认静音，震动需用户允许，切后台后不承诺精确唤醒。

任何步骤都有“退出工具”。退出后回到进入前页面，保留评估草稿；可另存为新登记，但不自动写入思虑库。

### 3.8 注销与删除

- 在“我的”中说明将删除当前用户全部业务数据，要求二次确认。
- 默认 cloud 调用 `deleteMe`，按 `deleting → 清理 → 删除用户` 完成两阶段注销，同代次可恢复中断清理；HTTP 模式调用 `DELETE /me`。成功后清除本地身份、敏感缓存与离线队列，返回登录页。
- 失败或仍在清理时不显示“已删除”，保留重试入口；旧代次请求不得写入重新登录后的新账号。

## 4. 页面状态、异常与空态

| 页面/组件 | 加载中 | 空态 | 异常与恢复 |
|---|---|---|---|
| 此刻 | 轻量骨架，不阻塞应急入口 | “此刻没有待处理记录。需要时，先记下来。” | 首页统计失败仍可速记；显示非阻塞“统计暂未更新”。 |
| 速记面板 | 提交按钮进入忙碌态，禁止重复点击 | 初始仅保留必要提示 | 字段错误就地提示；断网提示“已存本机，联网后同步”；未知提交结果先核对再重试。 |
| 相似提示 | 不阻塞提交 | 不展示候选 | 匹配失败可跳过并作为新思虑登记。 |
| 处理队列 | 骨架列表 | “没有这一状态的记录”，可切回全部 | 分页失败保留已加载内容；提供重试。 |
| 七步评估 | 读取详情时显示步骤骨架 | 新版本预填为空时从当前步骤填写 | 保存失败保留本地草稿并标明“未同步”；关闭校验失败定位缺项。 |
| 思虑库 | 搜索防抖，保留旧结果 | 无记录时引导速记；无结果时提示更换关键词/筛选 | 查询失败不清空关键词；支持重试。 |
| 版本时间线 | 骨架节点 | 不应出现无版本思虑点；异常时隐藏详情并上报 | 无权限或已删除返回列表，不展示其他用户缓存。 |
| 统计 | 图表骨架或文本占位 | “完成几次记录后再来看趋势” | 统计失败不影响核心记录；不展示伪造的 0。 |
| 应急叫停 | 立即可用 | 无 | 不依赖接口；计时异常可退出，不影响其他功能。 |
| 登录/账号 | 登录中禁止重复提交 | 未登录只显示必要说明 | 401 引导重新登录；注销失败明确保留状态。 |

通用要求：错误文案说明“发生了什么、数据是否保留、下一步怎么做”；提供按钮而非只显示错误码，技术码写入日志。网络超时、服务器错误和权限失效不得共用“操作成功”反馈。

## 5. 低刺激交互规范

- 每屏一个主要行动，次要操作弱化；危险操作不使用鲜艳红色制造恐慌，但需文字明确。
- 动画 150–300 ms，收尾动画可跳过；尊重系统减少动态效果设置，无自动播放声音。
- 不使用连续签到、红点催收、失败惩罚或“你必须振作”等话术。
- 滑杆同时提供可读数值，点击区域不小于 44 × 44 pt；文本对比度、字号和焦点状态满足可读性。
- 情绪标签允许“其他”；不强迫语音、头像、昵称或精确时间录入。
- 后台切换、来电和微信会话返回后，优先恢复原文与步骤。

## 6. V1 验收路径

1. 微信登录 → 速记 → 稍后处理 → 处理队列可见。
2. 速记 → 相似提示 → 用户确认关联 → 新版本预填 → 独立收尾，旧版本不变。
3. 七步中途退出/断网 → 草稿保留 → 恢复 → 三项确认 → 服务端收尾成功。
4. 任一版本搁置后继续；已收尾版本只读。
5. 搜索、状态/情绪筛选、版本时间线及统计与接口返回一致。
6. 断网进入应急叫停，退出后回到原流程且草稿不丢失。
7. 注销成功后，本地敏感数据清空，再次登录不可见旧业务数据。
