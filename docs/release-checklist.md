# 「止念」发布工作清单

> 项目：`mind_trace`  
> 默认：`DATA_MODE=cloud`，微信云函数 `mindTrace` + 云数据库。
> 可选：`DATA_MODE=http`，Go API + 腾讯云 MySQL + Vue 3 管理端。
> 用法：先完成 **A. 通用清单**，再执行 **B. cloud 默认路径**或 **C. HTTP 可选路径**，最后完成 **D. 放行**。每项记录负责人、日期和证据；平台规则以控制台当期为准。

**审核时长不可控，不承诺微信审核、HTTP 备案或证书申请的具体完成时长。微信云服务套餐、价格与免费额度以控制台当期为准，不承诺固定免费。两种模式的数据不自动同步，Vue 管理端仅支持 Go + MySQL HTTP 模式。**

## A5. 功能、离线、兼容与安全验收

- [ ] 快速登记字段：触发事件 1–100 字、循环念头 1–1000 字、强度 1–10；概率 0–100。
- [ ] 七步草稿可保存/恢复，平衡视角三栏与三项确认未满足时不能收尾。
- [ ] 版本状态仅 `registered / evaluating / paused / closed`；思虑点状态仅 `active / resolved / recurring`。
- [ ] 相似匹配只提示；用户选择后携带 `thoughtId`，新版本继承评估字段、重置 `closeConfirmations`，旧版本不变。
- [ ] 每次登记生成并复用 `clientRequestId`；重复点击、并发及核对后的重试均返回首次结果，不重复创建。
- [ ] 弱网、断网、切后台、进程重启后，本地草稿和 outbox 不丢；网络结果未知或中断标记 `uncertain`，不盲目自动重发。
- [ ] 每条队列绑定 `ownerUserId + backendMode + backendEnv`；缺字段、账号/代次或环境变化标记 `blocked` 并保留本机。
- [ ] cloud 的 `ownerUserId` 包含 `${_id}:${generation}`；`backendEnv` 为 `CLOUD_ENV || 'default'`，HTTP 为 `API_BASE`。
- [ ] 应急叫停断网可用，退出后原草稿仍在，不新增接口外状态。
- [ ] 搜索、状态/情绪筛选、分页、空态、错误态、统计与所选模式返回一致；统计数据覆盖当前用户全部记录。

- [ ] 完成一次注销演练：云端业务数据不可再访问，本地敏感缓存清空，备份处理符合已公布规则。
- [ ] 日志、告警和控制台导出不包含思虑正文、令牌、AppSecret、`session_key` 或数据库密码。

## B3. 集合、安全规则与索引

- [ ] 创建 `users`、`thoughts`、`records` 集合；文档使用 `_id` 和普通业务归属字段 `ownerOpenid`。
- [ ] `users` 保存 `generation/deleting/deletingAt/lastWriteAt`；`thoughts` 保存 `versionCount/openCount`；时间统一存 ISO 字符串。
- [ ] 三个集合安全规则均为 `read:false`、`write:false`，直接客户端读写测试全部被拒绝。
- [ ] 云函数仍可正常读写，且每个业务查询/写入都强制 `ownerOpenid = 当前 OPENID` 归属。
- [ ] 创建 `users(ownerOpenid)` 唯一索引，防止重复用户。
- [ ] 创建 `thoughts(ownerOpenid,status,updatedAt)`、`thoughts(ownerOpenid,updatedAt)` 列表索引。
- [ ] 创建 `records(ownerOpenid,status,createdAt)`、`records(ownerOpenid,createdAt)` 查询索引。

## B4. 事务、注销、幂等与状态

- [ ] `createRecord` 使用 `db.runTransaction`；新思虑及首版本、复发递增均在事务内完成。
- [ ] `OPENID + clientRequestId` 经 SHA-256 生成确定性记录 `_id`，这是记录幂等 ID 而非公开用户 ID；同一用户重试返回首次记录。
- [ ] 创建事务校验活跃用户与代次，并在写业务文档前更新用户 `lastWriteAt/updatedAt`，与注销标记形成写冲突。
- [ ] 不同用户使用相同 `clientRequestId` 不互相命中；重试不增加 `versionCount`。
- [ ] 复发锁定思虑文档并递增 `versionCount`，并发版本不重复；继承评估字段但重置三项确认。
- [ ] `closeRecord` 在事务中校验记录和思虑文档，更新 `closed/openCount/status`。
- [ ] 版本数 ≥3 为 `recurring`；不足 3 且 `openCount=0` 为 `resolved`，否则 `active`。
- [ ] `deleteMe` 按“事务标记 `deleting` → 分批清理 records/thoughts → 事务复核代次并删除用户”执行。
- [ ] 同代次 `deleteMe` 可重入恢复清理；旧代次不能操作新账号，延迟清理不能删除新代次。
- [ ] 验证注销与 `createRecord` 并发不会留下标记注销后新增的业务记录；客户端核对包含代次的用户 ID。
